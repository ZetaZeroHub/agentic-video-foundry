# Agentic Video Foundry 波普艺术官网设计规格

日期：2026-08-18
状态：设计冻结，等待书面审核
目标仓库：`/Users/apple/Public/openProject/agentic-video-foundry`

## 1. 目标与边界

建设一个与 Agentic Video Foundry 宣传视频共用视觉语言的一页式中文产品官网。官网必须在首屏回答三个问题：它是什么、它解决什么问题、如何安装；并用真实仓库能力、真实命令和真实产物结构证明它不是只会生成抽象动效的概念项目。

唯一传播结论：**Agentic Video Foundry 把一句视频需求变成一套可复现、可验收、可交付的短视频生产线。**

主要受众：使用 Codex、Claude Code、Gemini CLI 等 coding agent 的内容创作者、开发者和小型团队。
主要 CTA：复制全局安装命令。
次要 CTA：访问 GitHub、查看真实工作流和案例说明。

本期不做：

- 登录、数据库、表单后台、评论或用户上传；
- 多语言、多路由文档站或在线编辑器；
- 运行付费音频、视频生成或云端渲染；
- 追踪脚本、广告像素或未经同意的分析；
- 把用户私人视频、付费生成素材、API Key 或本机路径提交到公开仓库。

## 2. 交付形态

在仓库增加独立 `website/` 目录，使用原生 HTML、CSS 和少量无依赖 JavaScript：

```text
website/
├── index.html
├── styles.css
├── site.js
└── README.md
```

该目录必须满足：

- 双击 `index.html` 可本地浏览；
- 可直接部署到 GitHub Pages 或任意静态托管；
- 不依赖 npm、框架、CDN 字体或远程运行时；
- 所有核心内容在 JavaScript 禁用时仍可阅读；
- `site.js` 只负责复制安装命令、导航状态和减少动效偏好，不负责生成页面正文。

首版不生成占位 favicon 或通用社交分享图。只有在官网内容与视觉已经实现并冻结后，才允许制作与成品一致的专用分享图；没有通过文字核对的分享图就不接入元数据。

本期不引入 Sites/Vinext。原因是当前需求只有一个公开产品页，原生静态站能以更低维护成本与开源仓库共存。未来出现多路由、持久化或动态内容后再单独迁移。

## 3. 页面结构

### 3.1 顶部导航

- 左侧：`AGENTIC VIDEO FOUNDRY`；
- 右侧：工作流、真实证据、案例、GitHub、安装 Skill；
- 移动端只保留品牌、GitHub 和安装入口，不实现复杂抽屉菜单。

### 3.2 Hero

主标签：`这套 Skill 正在剪自己`
主标题：`一句需求，到可交付成片`
补充文案：`脚本、画风、真实演示、配音、音乐、逐帧合成、质检与分轨交付，收进一条可复用的视频生产线。`

右侧使用仓库事实构成终端/制作面板，展示：

```text
使用 Agentic Video Foundry，制作一条介绍你自己的宣传片。
brief → storyboard → voice → timeline → render → audit
```

这部分是产品化展示，不伪造执行结果、百分比或不存在的模型。

### 3.3 证据数字条

- `1` 个主时间轴；
- `2` 套音频后端：ElevenLabs、火山豆包语音；
- `3` 类核心场景路线：Remotion、Text-to-Lottie、HyperFrames；
- `9` 段模块化宣传视频交付。

数字必须能在 README、Skill 或本次视频规格中找到对应事实。未来能力变化时统一更新，不使用夸张统计。

### 3.4 六步工作流

六张卡片依次为：

1. 诊断任务：受众、平台、时长、传播结论、CTA、证据；
2. 分镜与画风：镜头任务优先，再选择风格模块；
3. 声音生产：供应商路由、试听、对齐、旁白驱动时间轴；
4. 场景路由：Remotion 主链，Lottie 与 HyperFrames 作为有边界的支线；
5. 确定性合成：逐帧动画、代表帧、字幕与音画同步；
6. 验收交付：完整观看、手机外放、LUFS、dBTP、编码、manifest。

### 3.5 真实证据区

展示真实存在的命令与文件关系：

```text
npm run timeline
npm run stills
npm run render
audit-video-project.mjs --strict
```

公开官网不得展示本机绝对路径、终端用户名、密钥、供应商请求头或私人项目名称。终端文本来自仓库和参考工程的已验证命令；如果实现时命令发生变化，以仓库当前事实为准。

### 3.6 自剪自证与外部案例

第一层证据说明 Foundry 如何生成介绍自己的九段宣传片。第二层案例说明同一工作流曾用于 AI 游戏平台宣传片。

仓库宪法禁止提交用户媒体，因此首版公开站只提交案例文字、公开安全的概念标签和可选外部链接容器，不提交原始 MOV、截图或从私人视频导出的帧。未来只有在用户明确确认素材可公开且仓库规则允许后，才通过独立发布资产或外部托管接入。

案例文案不得宣称 AI 游戏平台视频已由新版官网管线重新制作，除非新成片完成并通过验收。


提供复制按钮、GitHub 链接、MIT License、兼容工具说明。复制失败时保留可手动选择的纯文本命令，并显示可读状态提示。

## 4. 视觉系统

官网使用 `comic-pop-art-motion` 风格模块的静态网页变体：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ink` | `#101010` | 轮廓、正文、硬阴影 |
| `--paper` | `#FFF7E8` | 主背景 |
| `--yellow` | `#FFD400` | 主 CTA、重点数字 |
| `--cyan` | `#00B7D9` | 证据区、流程强调 |
| `--red` | `#F2385A` | 钩子、警示、次级强调 |
| `--blue` | `#2457D6` | 标签与辅助分组 |

规则：

- 粗黑轮廓、硬边阴影、纯色块和局部固定网点；
- 同一视口最多三种高饱和颜色加黑白；
- 不使用玻璃拟态、霓虹、渐变、3D 翻转或持续漂移动画；
- 真实 UI 和命令区域保持原像素与高可读性，不加网点、套色或漫画滤镜；
- 中文标题使用系统粗黑体回退栈，不依赖外部字体；
- 链接、按钮、焦点和复制状态不能只靠颜色区分。

## 5. 交互与响应式

- 页面最大内容宽度约 1440px，桌面双栏，900px 以下切单栏；
- 首屏 CTA 在 390px 宽度下无需横向滚动；
- 顶部导航使用锚点跳转，尊重 `prefers-reduced-motion`；
- 复制按钮支持键盘、触摸和 `aria-live` 状态；
- 动效限于一次性 panel 进入、按钮按压和装饰性套色偏移；减少动效模式下全部关闭；
- 所有正文对比度达到 WCAG AA；主操作具有可见焦点环；
- 不阻止浏览器缩放，不使用仅悬停可见的信息。

## 6. 视频复用接口

官网同时作为宣传视频的真实录屏表面：

- Hero 用于第 01 段元叙事钩子；
- 工作流用于第 02、03 段任务与设计说明；
- 证据区用于第 04、06、07 段真实操作和质检；
- 安装区用于第 09 段 CTA。

录屏时网页占竖屏画面的 75%–88%，波普注释只做外围聚焦。网站本身不为录屏专门伪造数据；需要放大的内容通过浏览器真实缩放或裁切完成。

## 7. 验收

实现完成后必须验证：

- 本地静态打开和静态 HTTP 服务均可用；
- 桌面 1440px、平板 768px、手机 390px 无横向溢出；
- 锚点、复制按钮、键盘焦点和减少动效模式正常；
- 安装命令、能力名称、许可证和 GitHub 地址与仓库一致；
- 页面源码不含 API Key、本机绝对路径、私人媒体路径或追踪脚本；
- 真实证据区域在手机宽度仍可读，无法读清的命令允许横向滚动而不压缩变形；
- HTML、CSS、JavaScript 通过基本语法检查；
- Git diff 只包含批准的网站文件与相关文档，不提交用户媒体和付费资产。

## 8. 实施顺序

1. 创建静态站骨架和视觉 token；
2. 完成首屏、工作流与安装入口的最小可识别切片；
3. 补齐证据、案例、响应式和可访问性；
4. 本地构建与浏览器验收；
5. 用户确认后再决定 GitHub Pages 或其他静态托管发布，不在未授权时自动发布。
