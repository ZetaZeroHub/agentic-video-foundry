# Agentic Video Foundry 官网内容重构与小铸动效设计

日期：2026-08-21
状态：设计已在视觉伴侣中逐段批准，等待书面复核
范围：`website/` 英文首页、中文首页、共享样式、共享脚本与官网媒体资源

## 1. 背景

现有官网已经有完整的波普视觉、双语 SEO、视频播放器、音频供应商说明和风格切换。不过首页把内部实现、能力清单和用户结果放在同一层。第一次接触 Agent Skill 的访客需要先理解 `brief`、`routing`、`preset`、`deterministic composition`、`manifest`、`LUFS` 和 `dBTP`，才能判断它能不能帮自己做视频。

新宣传视频已经找到更自然的讲法：先让人看到结果，再解释它会先问什么、会写出哪些文档、怎样制作声音、怎样检查交付。官网应采用同一条叙事，同时保留开发者需要的安装、供应商、风格模板和技术约束。

## 2. 目标

1. 小白用户进入首页后，五秒内知道这套 Skill 能把一句需求做成可发布的视频。
2. 完整 V6 成片紧跟 Hero，先用实际作品建立判断依据。
3. 主阅读层使用普通用户能听懂的词，技术细节通过渐进披露保留。
4. 把视频里的吉祥物“小铸”带到官网，使用有语义的定格动画帮助理解关键步骤。
5. 英文为默认语言，中文结构与信息保持对等；两种语言都按母语习惯写，不逐字直译。
6. 保持当前波普块面、粗边框和高对比品牌特征，同时改善移动端阅读、键盘操作、动态效果降级和媒体性能。

## 3. 非目标

- 不把官网改成在线剪辑器或配置向导。
- 不增加账号、上传、付费、后端 API 或数据收集。
- 不在主阅读层展开音频 endpoint、渲染器选型、JSON 路径和响度参数。
- 不让吉祥物在每个 section 持续运动。
- 不把宣传视频逐字搬到网页；网页只保留适合扫描阅读的内容。

## 4. 核心叙事

采用“成片带路”方案：

1. 我能得到什么
2. 先看完整成片
3. 它开始前会问什么
4. 它怎样把一句想法写成能执行的方案
5. 旁白、音乐和音效怎样一起完成
6. 风格怎样选择和扩展
7. 导出后怎样检查和交付
8. 怎样安装并开始

主转化路径为“先看完整成片”。“安装 Skill”是 Hero 的次按钮，并在页面末尾成为唯一主按钮。

## 5. 逐 section 诊断与改法

### 5.1 Header

现状问题：工作流、音频、风格、成片、案例、GitHub、语言和安装全部平铺，导航密度过高。

改法：

- 主导航只保留“看成片 / Watch”“怎么做 / How it works”“风格 / Styles”“安装 / Install”。
- GitHub 与语言切换降为辅助入口，但仍可直接访问。
- 移动端使用一个有文本标签和 `aria-expanded` 状态的菜单按钮。
- Header 固定后必须为正文预留空间，不能遮挡锚点标题。

### 5.2 Hero

现状问题：脚本、真实演示、AI 口播、音乐、音效、字幕、渲染和质检被塞进同一段。供应商、兼容工具和终端卡片同时抢占第一视觉。

中文主文案：

- 标签：`这条宣传片，是它自己做的`
- 标题：`说清你想做什么 / 拿到能发布的视频`
- 正文：`它会先问清楚发给谁、发到哪、讲多久，再帮你写脚本、做分镜、配声音、排字幕，最后把完整视频和可编辑素材一起交给你。`
- 案例标注：`本页成片实测：半天完成 · 4+ 轮对话 · 9 段可拆`
- 主按钮：`先看完整成片`
- 次按钮：`安装 Skill`

英文主文案：

- Label: `This launch video was made by the Skill itself`
- Heading: `Describe the video. / Get something you can publish.`
- Body: `It asks who the video is for, where it will be posted, and how long it should run. Then it writes the script, plans the shots, builds the audio and captions, and delivers the finished video with editable parts.`
- Case note: `This page's video: half a day · 4+ conversations · 9 reusable chapters`
- Primary CTA: `Watch the full video`
- Secondary CTA: `Install the Skill`

小铸出现在 Hero 右侧，播放一次挥手和指向动作后停住。兼容 AI 工具的 Logo 放在 Hero 底部单独一行，不与主标题并列竞争。

### 5.3 案例实测条

现状问题：`1 个主时间轴 / 2 套音频后端 / 3 类场景路线` 描述的是内部架构，普通用户看不出价值。

替换为本次官网视频的实测信息：

- 半天完成
- 4+ 轮对话
- 9 段可拆 MP4
- 旁白、音乐、音效和案例声分轨

必须标明这是本次案例数据，不能暗示所有视频都能在半天内完成。

### 5.4 完整成片

现状问题：视频出现在大量技术说明之后，且页面仍显示旧版 168 秒数据。

改法：

- 把最新 V6 完整成片移动到 Hero 后。
- 标题：`这套 Skill 到底能做什么，看完就知道`。
- 说明：`下面这条视频就是它从一句需求开始做出来的。默认静音，想听配音和音效时再打开声音。`
- 使用不透明画布。视频与页面背景不能叠在一起。
- 进入视口后默认静音播放；必须保留显式播放、暂停、开关声音和播放状态。
- `prefers-reduced-motion: reduce` 下不自动播放。
- 使用最新真实时长，不手写旧秒数；界面优先从媒体元数据读取时长，结构化数据使用构建时确认值。

### 5.5 开始前先问清楚

现状问题：原六张 Workflow 卡片使用 `Brief`、`Routing`、`Deterministic composition` 和 `manifest` 等项目汇报语言。

新标题：`发给谁，发到哪，准备讲多久`。

正文：`同一句话，发小红书和发 B 站，写法完全不同。它会根据平台、观众和时长调整开头、信息密度和镜头节奏。`

页面用四个明确例子解释方法：

- 给新手：先讲结果，少用术语。
- 给专业用户：保留方法和参数。
- 短视频：更快进入重点。
- 长视频：把来龙去脉说完整。

小铸从右侧进入，使用思考动作。受众、平台和时长卡片跟随动作依次出现。

### 5.6 四份文档

新标题：`四份文档，把一句想法变成能执行的方案`。

- 目标简报：这条片给谁看，要让人记住什么。
- 分镜表：每个镜头出现什么，旁白说到哪里。
- 视觉规范：颜色、字体、动效和吉祥物怎么动。
- 独立小样：先把最难的镜头做出来，满意后再铺开。

四张文档按阅读顺序出现。小铸只在这一组开始时播放一次翻页和核对动作，不跟随每张卡重复跳动。

### 5.7 声音

现状问题：当前供应商能力矩阵包含 API 名称、时间戳字段和响度术语，像接入文档。

新标题：`选声音，配旁白，加音乐，再把字幕跟准`。

正文：`Skill 已经接入 ElevenLabs 和火山引擎。它能试听不同音色，生成旁白、背景音乐和动作音效，再让字幕跟着真实口播走。你听到不合适的声音，可以换；音乐太小或太抢，也可以直接调。`

主层展示声音工作顺序和两个供应商 Logo。API、字幕时间戳、声音复刻授权、重新测量响度等内容放入可展开的“查看接入细节”。小铸播放试听和打拍子动作。

### 5.8 风格

现状问题：用户还没有看到视觉结果，就先读到 `preset`、`token`、硬失败和 JSON 路径。

新标题：`先选一种，也可以加自己的`。

正文：`波普艺术适合节奏快、颜色亮的宣传片；手撕纸适合更温和、更有质感的故事。每套模板都会约束配色、字体和动作方式，避免每个镜头各长各的。现成模板不合适，还可以继续添加新的。`

主层先展示两个可操作小样。颜色、运动参数、路径和禁止项放入展开面板。切换风格时不得改变 section 高度造成大幅布局跳动。

### 5.9 检查与交付

新标题：`从头看一遍，再从头听一遍`。

正文：`字幕有没有少字，手机外放能不能听清，转场有没有爆音，文件还能不能继续剪。都过了，再把完整视频、独立章节、音频分轨和字幕交给你。`

使用四个可读检查项，不显示 LUFS、dBTP 等测量值。技术报告仍可通过“查看验收细节”打开。小铸使用放大镜和勾选动作。

### 5.10 “用自己剪自己”与案例

现状问题：Meta Demo、Case Study 和完整成片分成三段，重复解释同一条证据。

改法：

- “用自己剪自己”缩成 Hero 标签和成片旁的一句说明。
- AI 游戏平台宣传片保留在完整成片内部，不再另做三张抽象案例卡。
- 如果以后增加第二个真实案例，再恢复独立案例区；只有一个案例时不创建空洞的案例目录。

### 5.11 FAQ

FAQ 改为普通用户实际会问的问题：

1. 我不会剪辑，也能用吗？
2. 可以带自己的图片、录屏和已有视频吗？
3. 声音和画风不喜欢，能换吗？
4. 做完以后还能继续修改吗？
5. 支持哪些 AI 工具？
6. 使用 ElevenLabs 或火山引擎需要额外费用吗？

安全、凭据和声音复刻授权仍需回答，但不能占据 FAQ 的第一位置。

### 5.12 安装与 Footer

安装标题：`把它装进你常用的 AI 工具`。

正文：`复制安装命令，重启 Codex、Claude Code、Trae、WorkBuddy、Manus 或其他兼容工具，然后直接告诉它你想做什么视频。`

安装区包含：

1. 一条全局安装命令。
2. 复制按钮与可访问状态提示。
3. 三步说明：复制命令、重启工具、描述视频。
4. GitHub 仓库链接。

Footer 只保留项目名、`video.zzh.app`、GitHub、许可证和语言入口。

## 6. 小铸吉祥物系统

### 6.1 资产

复用 V6 宣传视频已经确认的角色设计，不生成第二套形象。官网使用五组动作：

1. `intro`：挥手和指向
2. `diagnosis`：思考
3. `documents`：翻页和核对
4. `audio`：试听和打拍子
5. `qc`：放大镜和勾选

每组 2 至 3 帧。资源放在 `website/assets/mascot/`，保留透明 PNG 源文件，并生成 WebP 或 AVIF 网页版本。HTML 明确声明宽高或 `aspect-ratio`，避免图片加载导致布局位移。

### 6.2 动效

- 帧切换使用定格动画，不做透明渐变或形变插值。
- 动作帧以约 140 至 220 毫秒的不等长停顿播放，走完后停住约 1.2 秒，再循环。
- 只有进入视口的动作运行；离开视口、页面隐藏或系统要求减少动态效果时暂停。
- Hero 只播放一轮后停住，其他解释型动作在可见期间间歇循环。
- 同一视口最多有一组小铸动作运行。
- 动画只能使用 `transform`、帧图切换和必要的 `opacity` 状态，不修改布局宽高。

### 6.3 无障碍

- 每组角色只保留一次有意义的替代文本，重复动作帧使用空 `alt`。
- `prefers-reduced-motion: reduce` 下显示静态第一帧。
- 角色不能遮挡正文、按钮、视频控制或焦点指示。
- 角色不是完成任务的唯一提示。所有动作表达的含义都由文字同步说明。

## 7. 页面结构与模块边界

官网继续使用静态 HTML、共享 CSS 和原生 JavaScript，不引入前端框架。

- `website/index.html`：英文默认页。
- `website/zh/index.html`：中文页，与英文页使用相同 section 顺序和 DOM 语义。
- `website/styles.css`：品牌 token、响应式布局、卡片、动效与 reduced-motion。
- `website/site.js`：Header、语言偏好、复制按钮、视频播放、风格切换和小铸动画控制。
- `website/assets/mascot/`：角色动作资源。

JavaScript 模块之间不共享隐式状态。视频播放器失效时不影响文案和安装；风格切换失效时默认展示波普样式；小铸动画失效时显示静态第一帧；复制 API 不可用时选中命令供手动复制。

## 8. 交互与数据流

1. 页面加载后读取语言偏好，仅执行语言跳转，不阻塞正文渲染。
2. `IntersectionObserver` 分别管理视频和当前可见的小铸动作。
3. 视频进入视口且未开启 reduced-motion 时静音播放，离开后暂停。
4. 小铸进入视口后按该动作的帧时长数组切换图片，离开后清理计时器并回到第一帧。
5. 页面隐藏时暂停所有媒体与计时器，返回后只恢复仍在视口中的模块。
6. 风格 Tab 保持现有键盘左右键操作和 `aria-selected` 状态。

## 9. 视觉与响应式

- 保留暖纸白、墨黑、电光黄、亮青、热红和钴蓝。
- 每个 section 只允许一个视觉主角；小铸、视频和文档卡不能同时争夺主视觉。
- 正文移动端不小于 16px，行高 1.5 至 1.75。
- 桌面正文行宽控制在约 65 至 75 个英文字符；中文按视觉宽度控制。
- 断点验收：375、768、1024、1440 像素。
- 交互控件最小点击区域 44×44px，键盘焦点清晰可见。
- 所有图片和视频预留尺寸，目标 CLS 小于 0.1。

## 10. SEO 与国际化

- 保留英文默认页、中文 `/zh/`、canonical、hreflang、Open Graph、Twitter Card、SoftwareApplication、HowTo 和 FAQ 结构化数据。
- 更新结构化数据中的描述、FAQ、视频时长和页面能力，使其与新正文一致。
- 英文文案按英语阅读习惯改写，不复制中文句式。
- 中文不混用 `preset`、`routing`、`Hero`、`manifest` 等非必要英文词。
- 兼容工具和供应商名称使用官方写法与官方 Logo；新增 WorkBuddy 和 Manus 前先核对官方品牌资产。

## 11. 错误处理与降级

- 视频文件不可用：显示封面、明确错误文字和 GitHub 链接，不留下黑色空框。
- 自动播放被浏览器阻止：显示“点击播放”，不重复尝试。
- Clipboard API 不可用：选中安装命令并提示手动复制。
- IntersectionObserver 不可用：视频和小铸保持手动或静态模式。
- 图片加载失败：角色区域保留尺寸但隐藏破图图标，正文继续可读。
- localStorage 不可用：语言链接仍然正常跳转，只是不保存偏好。

## 12. 测试与验收

### 内容

- 中英文 section 顺序、链接目标和事实一致。
- 主阅读层不出现 `routing`、`deterministic composition`、`manifest`、endpoint、LUFS、dBTP。
- `半天完成` 与 `4+ 轮对话` 明确标为当前案例实测。
- 页面不再显示旧版 168 秒数据。

### 功能

- 视频自动静音播放、暂停、声音切换和状态提示正常。
- 复制安装命令成功；失败时能手动复制。
- 风格 Tab 可点击并可用左右方向键操作。
- 小铸只在视口内运行，页面隐藏后停止计时。
- 无 JavaScript 时仍可阅读正文、播放视频和复制命令。

### 视觉与无障碍

- 在 375、768、1024、1440 像素宽度无横向滚动。
- 正常文本对比度至少 4.5:1。
- 所有互动目标至少 44×44px。
- 键盘可完成导航、视频控制、风格切换、FAQ 和复制操作。
- reduced-motion 下视频不自动播放，小铸静止，内容不缺失。
- 图片和媒体加载不造成明显布局跳动。

### 性能

- Hero 只预加载首屏必要资源。
- 完整视频使用 `preload="metadata"`，封面优先显示。
- 下方小铸动作资源延迟加载。
- 优化后的小铸单帧目标为 15 至 30KB；如果无法在不破坏边缘质量的前提下达到，则以视觉质量为准并记录最终大小。

## 13. 实现文件范围

预计修改：

- `website/index.html`
- `website/zh/index.html`
- `website/styles.css`
- `website/site.js`
- `website/assets/mascot/*`

不修改 Skill 的制作宪法、视频工程、音频供应商脚本或仓库根 README，除非实现阶段发现官网描述与仓库公开事实冲突；这类冲突必须单独列出再决定是否扩大范围。

## 14. 完成标准

一个第一次访问、不了解 Remotion、Lottie 或音频 API 的用户，滚动首页后能够回答：

1. 这套 Skill 能替我完成哪些视频工作？
2. 它开始前会问我什么？
3. 我会拿到哪些中间方案和最终文件？
4. 声音与画风能不能换？
5. 我可以在哪些 AI 工具中使用它？
6. 怎样安装？

同时，开发者仍能通过展开区、FAQ 和 GitHub 找到供应商、技术路线、安全边界和可扩展模板信息。
