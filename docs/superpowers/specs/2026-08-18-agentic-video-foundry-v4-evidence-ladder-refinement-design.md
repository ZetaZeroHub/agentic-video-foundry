## 1. 本轮目标

在当前 V4 波普艺术宣传片基础上重排为 88–92 秒版本，主叙事采用“证据阶梯”：先以“自己剪自己”和账单数字建立钩子，再依次证明需求诊断、画面规则、真实操作、成本与工具、声音、渲染、质检和外部案例。

本轮同时关闭以下已知缺陷：

1. 画面存在较多抽象动画，真实操作与实用证据不足；
2. 第二章四项诊断只列标签，未解释判断如何影响后续制作；
3. 第三章画面规则不够直观；
4. 第六、七章主题动画表现力不足；
5. 案例压轴的播放画布半透明，与背景重复叠加；
6. 字幕为适配节拍而截断完整语义；
7. “brief 与分镜”和“不等于发布”之后存在刺啦爆音；
8. 视频未明确展示 Token、费用、工具、安装和提示词逐步展开过程。

## 2. 传播策略

唯一传播结论：**这套 Skill 能用自身工作流剪辑并证明自己，而且所有结果都能回到真实输入、真实文件、真实音轨和真实质检。**

叙事结构采用“B 证据阶梯”为主体，吸收“A 账单先行”的高价值钩子：

- 开头先说“这条片，是它自己剪自己的”；
- 紧接着露出“本轮约 24 美元”；
- 费用只作为入口，不把整片做成成本挑战；
- 中段通过真实安装、对话、文件、预览和账本解释数字从何而来；
- 结尾用 AI 游戏平台宣传片证明工作流可用于外部项目。

## 5. 章节画面设计

### 5.1 第一章：自己剪自己

- 从真实 Remotion 时间轴或 Codex 预览中展示本片正在播放；
- 拉远一次，证明“画面中的片”就是当前片；
- “约 $24”作为波普账单贴纸落下；
- 不在开场堆叠 Token、工具名和公式。

### 5.2 第二章：四项诊断

四张卡必须成为四条因果链，而不是四个静态标签：

| 判断项 | 必须展示的后续影响 |
| --- | --- |
| 受众 | 决定中文表达、术语密度和说明深度 |
| 平台 | 决定 9:16、平台安全区和字幕位置 |
| 时长 | 决定信息密度、镜头预算和旁白长度 |
| 证据 | 决定使用实机界面、数据、文件还是外部案例 |

四条线依次接通，每次只高亮一条。最终汇合为 `brief → storyboard → preview`。

### 5.3 第三章：画面规则

规则以现场演示表达：

- 刚性纸片平移、分级旋转和等比缩放；
- 弯曲、液化、无路径瞬移和主体遮挡被红色禁用章击退；
- 安全区框、字幕块和主体自动吸附到合法位置；
- 每个元素从画外或纸片遮罩后进入，并以可见路径离场；
- 动效可以夸张，但不得频闪、连续抖动或破坏可读性。

### 5.4 第四章：实机过程

真实证据顺序：

1. 终端执行准确安装命令；
2. Codex 中输入一句目标；
3. 对话逐步补充平台、时长、风格和证据要求；
4. 文件树生成 `brief`、`storyboard`、`style-spec`、音频计划和预览资产；
5. 本地预览页更新；
6. 修改意见落到真实文件与新预览。

录屏必须脱敏，不显示 API Key、账户信息、私人目录或无关项目。

### 5.5 第五章：成本账本

- 主数字：`35.64M TOKEN` 和 `≈ $24`；
- 工具票据：Codex、Remotion、火山音频；
- 对话轨迹：`做个视频 → 诊断 → 分镜 → 试听 → 预览 → 返修 → 质检`；
- 安装方式用一条真实命令或官网安装入口表示；
- 不展示复杂价格公式。

### 5.6 第六章：声音工作台

- 使用真实旁白波形，不用随机柱状图冒充；
- A/B 试听卡依次播放同一句短文案；
- 旁白、BGM、SFX 三条轨道有明确标签；
- 推子变化与真实混音状态一致；
- 图标组：麦克风、声纹、耳机、节拍器、响度表；
- 音乐在手机外放上可感知，同时不遮挡旁白。

### 5.7 第七章：渲染编排

自绘三组波普图标：

- Remotion：胶片与时钟，代表唯一主时间轴；
- Lottie：矢量节点贴纸，代表冻结动画资产；
- HyperFrames：浏览器舞台，代表合适的 HTML/GSAP 场景支线。

三条支线以不同纸片轨道汇入主时间轴，随后输出独立 MP4、旁白轨、BGM 轨、SFX 轨和字幕卡。不得让 Lottie 或 HyperFrames 看起来像第二条主时间轴。

### 5.8 第八章：质检机器

把安全区、完整字幕、编码、响度和真峰值组成一台可运行的质检机器：

- 每项通过后落一个绿色章；
- 失败项用红线退回对应轨道；
- “渲染成功”只代表生成文件，不等于可以发布；
- 人工完整观看和收听在真正完成前不得自动勾选。

### 5.9 第九章：案例压轴

素材：`/Volumes/Lenovo/things/fcpx/创作游戏如此简单2/创作游戏如此简单2.mov`。

- 中央使用 100% 不透明的 16:9 播放画布；
- 播放画布底色为纯黑，不使用透明度、复制层或模糊背景层；
- 波普背景只位于画布外围，承担舞台和章节标签作用；
- 选取 10–12 秒高信息密度片段：钩子、能力板、AI 实时修改、可玩结果；
- 真实案例画面本身不加半透明滤镜。

### 5.10 第十章：CTA

只保留项目名、准确安装入口和“装上它，开始你的下一条”。不在最后四秒新增卖点。

## 6. 字幕规则

1. 一个字幕单元必须对应完整语义句；
2. 字幕从该句首个有效音素出现前少量预滚开始，持续到句末口播结束；
3. 长句允许两行，必要时允许同一句内部视觉换行，但不得提前切换下一句；
4. 只在句号、问号、感叹号或明确完整分号后切换；
5. 不以场景节拍为理由截断句子；场景时长应服从旁白；
6. 任何 TTS 重新生成都会使旧字幕时间失效，必须重新对齐。

## 7. 两处爆音修复方案

已知故障点：

- 第二章“在写 brief 与分镜”口播结束后约一秒；
- 第八章“渲染成功，不等于发布”口播结束后附近。

实施时必须：

1. 分别导出旁白、BGM、SFX 和混音轨；
2. 对故障点前后各一秒检查波形、峰值和样本不连续；
3. 单独试听每条 stem，确认是音效素材、切点毛刺、编码边界还是叠加削波；
4. 若为错误宽带音效，直接移除或替换，不以降音量掩盖；
5. 若为编辑点不连续，对源片段加短淡入淡出或等功率交叉淡化；
6. 重新渲染最终编码 MP4；
7. 复测 LUFS、dBTP 与转场峰值，并以耳机、笔记本扬声器和手机外放完整听完母带。

## 8. 技术与交付约束

- Remotion 继续作为唯一主合成器；
- 所有动画由帧值驱动，禁止 `Date.now()`、CSS animation、运行时计时器和无种子随机数；
- Text-to-Lottie 与 HyperFrames 只输出冻结、有哈希的支线资产；
- 仍交付每章 mixed/clean MP4、voice/BGM/SFX/mix WAV、SRT 和完整母带；
- 所有 WAV 为 48 kHz；
- 每章音轨长度与 MP4 精确一致；
- 新版验证通过前保留当前 V4 作为回退资产。

## 9. 验收标准

- 总时长由真实旁白决定，目标 88–92 秒；
- 十章均有明确证明任务，无纯装饰章节；
- 第二章四项诊断的因果关系可读；
- 第三、六、七、八章动效丰富但不牺牲阅读；
- 第四章包含真实安装、对话、文件和预览；
- 第五章准确显示 `35.64M Token` 与 `约 $24`；
- 第九章中央播放画布完全不透明；
- 所有口播字幕语义完整并常驻到句末；
- 两处已知爆音在最终编码文件中消失；
- 代表帧、安全区、编码、LUFS、dBTP 和人工完整视听全部通过；
- 用户人工审核最终成片后才能宣布完成。
